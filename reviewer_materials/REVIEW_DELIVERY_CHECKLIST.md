## D. Why the original bundle, and not a rebuilt one, must be sent

- Rebuilding the bundle from the same commit (`git bundle create … main`) produced a file with a **different
  checksum**: `28ccee07…` instead of `3f3f87f1…`. Git can pack identical objects in a different order.
- Both bundles verified and contained the same 570 objects and the same commit `a48eaac`. But only the original
  file's checksum is recorded in the manifest (revision 3) and in this checklist.
- Sending a rebuilt bundle would break the chain of recorded checksums and leave the reviewer unable to confirm
  they hold the artifact that was documented.
- **Send `docs/review_handoff_v1/nq_bot_a48eaac.bundle` exactly as it is.**
- The overlay archive, by contrast, is byte-reproducible (`0c23df51…` on rebuild).

## E. Reconstruction steps for the reviewer

```
git bundle verify nq_bot_a48eaac.bundle
git clone -b main nq_bot_a48eaac.bundle nq_bot && cd nq_bot
git rev-parse HEAD                        # a48eaac8d7825ef8171d9762de27fcc33b3d3798

# check all 55 entries of WORKING_TREE_INVENTORY.txt by SHA-256

```

**Line endings.**
- On Windows with `core.autocrlf=true`, 59 tracked files are checked out with CRLF.
- The inventory covers only the 55 overlay files, which the archive stores byte for byte.
- One pinned tracked file, `runs/rollmap_MNQ.json`, hashes differently under LF and CRLF (manifest HF-2). This
  affects only a real-data run, which is not part of the review.
